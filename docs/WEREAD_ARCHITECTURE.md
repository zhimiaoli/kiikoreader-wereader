# 微信读书功能说明

本文说明 Metalio S31 固件中微信读书功能的模块边界、主要流程和本地数据位置。微信读书服务端接口由官方客户端使用，协议及服务端策略可能变化；本功能属于社区实现，非腾讯官方产品。

## 功能概览

- 主导航提供微信读书书架入口，页面沿用固件已有书架组件、分页和系统字体设置。
- 扫码登录、账户退出、书架同步、封面同步、章节缓存、阅读进度上传/下载均通过后台任务执行。
- 缓存书籍生成可由本地阅读器直接打开的 EPUB，章节目录与插图优先走章包（`tar` 字段）一次取回。
- 缓存按章落到暂存目录，失败只丢当前章，下次缓存从缺口继续；全部就绪后才统一组装 EPUB。
- 缓存书籍仍复用本地阅读器的目录、翻页、字体、排版、书签和本地进度能力。
- 对已识别的微信读书缓存书籍，阅读器可额外累计并上报阅读时长；网络不可用时按页面交互决定连接 Wi-Fi 或仅离线阅读。
- 账户页展示本地统计的今日/累计上报值；它们是客户端记录，最终是否计入以服务端响应为准。

## 模块关系

```text
主导航 / app_registry.c
        │
        ├── app_weread.c ── 书架、账户、登录、操作弹窗、Wi-Fi 返回
        │       │
        │       └── weread.h / weread.c ── worker、登录态、书架、任务队列、计时上报
        │                ├── weread_protocol.c ── WeRead HTTP、流式响应和接口协议
        │                └── weread_epub.c ── 章节/图片下载与本地 EPUB 写入
        │
        └── app_book.c ── 普通本地阅读器；识别缓存书并调用时长计时接口
```

## 交互与数据流

1. **进入书架**：从导航进入微信读书页面；检测现有登录态，按需验证后加载本地保存的书架元数据。联网同步任务更新书目并按顺序处理封面。
2. **选择书籍**：弹窗根据本地缓存情况启用/禁用打开、缓存、上传进度、下载进度等操作。耗时操作在 worker 中执行，页面轮询状态和进度。
3. **缓存书籍**：先取章节目录（内存 10 分钟 + SD 卡 7 天双层缓存）。每章按"阅读页取 psvts → 3 个正文分片"取回；章节目录里的 `tar` 字段命中时，一次请求取回整章插图包（tar 或 zip）并在本地解包，未命中的外链图才逐张下载，且按 URL 全书去重。章节正文用内存缓冲直接生成 XHTML，写完落盘后再写 `meta`（章节 uid、字节数、CRC32），因此任何一章失败只丢该章，下次缓存从缺口继续。全部章节就绪后统一组装 EPUB 并校验章数，成功才替换书架文件，随后删除暂存目录。
   分章阅读走同一套章节存储但不等全书：`wr_open_book()` 在书籍路径上写一份自描述标记文件，阅读器打开时由 `weread_cache.c` 的虚拟书源直接供给章节（未缓存章节返回占位正文，目录始终是全书），后台 `WR_PREFETCH` 任务按 10 章窗口补齐，读者正在等待的章节优先。整书组装完成后标记文件被真正的 EPUB 原子替换，路径不变，进度与书签连续。详见 `docs/WEREAD_CHAPTER_CACHE_DESIGN.md`。
4. **阅读**：本地阅读器负责渲染与翻页。仅符合微信读书缓存标记且登录/联网条件满足时启动额外的时长报告；阅读器页的网络与显示刷新策略相互独立。
5. **离线续开**：离线打开已缓存书时询问是否连接 Wi-Fi 启用时长上报。用户连接成功返回后，导航层应直接续开目标书，不先绘制微信读书书架中间页。
6. **账户切换**：退出登录时可选择保留缓存；登录新账户时按实现清理旧账户书架元数据，保留的 EPUB 按本地书籍处理。

## 本地数据与安全

- 微信读书模块的数据根目录由 `main/book/weread_internal.h` 中的 `WR_DIR` 定义（当前为 `/sdcard/.weread`）。
- 登录凭据保存在 ESP-IDF NVS 命名空间 `weread` 中；请勿提交真实 Cookie、二维码、账户 ID、设备日志或包含凭据的 NVS 导出文件。
- EPUB/图片缓存写在 SD 卡，账户元数据和阅读统计按代码路径持久化。清理账户状态前应核对保留缓存选择。
- 章节暂存在 `/sdcard/.weread/stage-<账号>-<书籍>/`（`t/` 正文、`i/` 插图、`m/` 校验），缓存成功后自动删除；章节目录缓存位于 `/sdcard/.weread/toc/`。
- 整包请求优先复用同一条 keep-alive 连接（服务端返回 gzip 时本地解压），连接层失败会自动退回一次性连接的完整路径；分块读取的阅读页与进度上报仍走一次性连接。
- `weread.qq.com` 的非公开接口可能调整、限流或撤销会话；失败时需区分网络/TLS、认证、响应解析、章节下载和 SD 写入错误。
- 阅读时长由设备侧活动计时产生并经网络上报，屏幕显示或本地累计不能替代服务端确认。

## 调试建议

按页面操作复现时，先确认 Wi-Fi 已连接，再查看 `WEREAD`、`app_loop`、`app_book` 和 Wi-Fi 组件日志。同步/下载失败需要保留失败阶段及 HTTP 状态；打开 EPUB 后重启则同时检查文件读取、阅读器解析和内存水位。日志分享前请移除 Cookie、二维码内容、账号标识和个人书籍信息。
