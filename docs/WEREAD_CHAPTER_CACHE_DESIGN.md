## 1. 验证 A：章节级图文缓存

### 1.1 逐项结论

| 需求 | 实际数据来源 | 结论 |
| --- | --- | --- |
| 章节标题 | `chapterInfos[].title` | 可得；已缓存进 `wr_chapter_t.title` |
| 章节 ID | `chapterInfos[].id` | 可得；写入 `m/c<N>.meta` 的 `uid` |
| 章节顺序 | `chapterInfos` 数组顺序 + `index` 字段 | 可得；本次以数组顺序作为 spine 顺序 |
| 正文 | `wr_chapter_content()`：阅读页取 psvts → 3 个正文分片 → `restore_order()` → base64 解码 | 可得，单章独立 |
| 图片引用关系 | `render_html()` 解析 `<img src>` / `<image xlink:href>`，重写为扁平文件名 | 可得，且已被重写为自洽形式 |
| 图片资源 | `chapterInfos[].tar` 章包（tar 或 zip）优先；未命中的外链逐张下载 | 可得 |
| 重复图片 | 图片名 = `fnv1a64(URL)` 前 48 位 + 扩展名 | 天然按 URL 全书去重 |
| 相对路径 | 重写后不再有相对路径，全部是扁平名 | 不会出现路径穿越或解析歧义 |
| 资源缺失 | 逐张下载失败时该 `<img>` 整段丢弃，保留文字 | 不产生坏图引用 |

### 1.2 关键结论：单章可以独立成篇

`stage_chapter()` 产出的 `c<N>.xhtml` 是**自洽的**：图片引用不指向章节文件之外的相对目录，而是指向同一个扁平命名空间（组装后就是 EPUB 根目录）。因此"只缓存一章就能读"在数据层成立，不依赖其他章节。

### 1.3 已知限制（真实存在，不掩盖）

- **正文成功 ≠ 图文完整**：章包（`tar`）过期或缺失时走逐张下载，单张失败只会丢图，章节仍会被标记为可用。当前不做"缺图即整章失败"，因为那会让图片多的书几乎无法缓存。若需要严格完整性，应在 `stage_chapter()` 增加"缺图计数 → 该章标 STALE"的策略（未实现）。
- **GIF 被主动跳过**：原生阅读器只渲染 png/jpeg/webp，写入 GIF 只会得到坏图引用。

## 2. 验证 B：原生阅读器动态章节加载（本项目最关键验证）

### 2.1 原生解析器的真实约束

读 `main/book/book_epub.c` 的实际实现，可确认三件事：

1. `book_epub_open(path)` 的第一步是 `zip_open(path)`，即**必须先有一个完整 ZIP**。
2. 之后所有内容访问只有 5 种原语：`zip_find` / `zip_entry_name` / `zip_entry_size` / `zip_extract` / `zip_extract_prefix`（外加 `zip_entry_count`、`zip_prefetch_step`）。
3. 没有任何"条目提供方"抽象；章节、图片、CSS、字体全部按名字从 ZIP 取。

**结论：原生解析器不支持"按需数据源"**，且 ZIP 不可原地追加条目（中央目录在尾部、偏移固定）。

### 2.2 为什么否决"多个独立 EPUB 拼接"

- spine 序号即章节号，进度/书签/目录全按 spine 索引与累计字节；
- 拼接会产生不连续的编号与错误的 `chapter_byte_offset()`，书签和云端进度立刻失真；
- 打开一个"目录里有 500 章、实际只有 3 个文件"的假 EPUB 会让 `package_parse()` 在 manifest 解析阶段失败。

### 2.3 选定方案：虚拟书源适配层（Virtual Book Source）

不改排版引擎，只改"条目从哪来"。

```
book_source.book_open(path)
   └─ 优先问虚拟解析器 book_set_virtual_resolver()
        ├─ 命中（路径上是微信读书标记文件）→ book_epub_open_virtual(provider)
        └─ 未命中 → book_epub_open(path)  ← 旧 EPUB 走原路径，行为不变

book_epub 内部
   ├─ EPUB 模式：epub_find() → zip_find() …
   └─ 虚拟模式：epub_find() → provider.entry_*()
                    └─ /sdcard/.weread/stage-<账号>-<书籍>/t/c<N>.xhtml、i/<hash>.<ext>
```

**命名空间与组装后的 EPUB 完全一致**（扁平：`c<i>.xhtml` + 图片名），因此：

- 排版、分页、字体、行距、边距：**零改动**（`book_layout.c` 未修改）
- 书签、阅读位置：**零改动**（仍按 spine 序号 + 章内字节偏移）
- 目录：走原生"无正式目录时按 spine 生成"的回退路径，标题由提供方注入书内字符串池 → **零下载时目录就是全书的**
- 未缓存章节：返回占位 XHTML（"正在缓存本章…"），可排版、可翻页、可停留，不会白屏或报错

### 2.4 改动面（可审计）

| 改动 | 规模 |
| --- | --- |
| 新增 `epub_find/entry_name/entry_size/extract/extract_prefix/entry_count/prefetch` 7 个适配函数 | 约 60 行 |
| 53 处 `zip_*` 调用点机械替换（同签名、同参数顺序，仅多一个接收者） | 53 行级替换 |
| 新增 `book_epub_open_virtual()` | 约 50 行 |
| `book_epub_close()` 分支释放 provider | 3 行 |
| `book_source` 解析器注册与优先派发 | 约 20 行 |

`zip_open/zip_close` 之外的 ZIP 行为未改变；旧 EPUB 打开路径一个字节都没动。

### 2.5 备选方案与否决理由

| 方案 | 做法 | 否决理由 |
| --- | --- | --- |
| B. 整本重组 | 每跳一章就用已缓存章节重写一个完整 EPUB | 写放大 = 全书体积/次（20 MB 书约 2–5 s/次）；断电风险高；跨章翻到边界必然重建 → 否决，仅保留为"缓存全书" |
| C. 独立阅读页 | 为微信读书另写目录/翻页 | 直接违反"不重写原生阅读引擎"，且书签/进度/按键全部要重做 |
| D. 仅缓存首章再阻塞 | 用户等整本 | 正是本次要解决的问题 |

### 2.6 已实现 / 未实现

- 已实现：解析层适配、provider、章节存储、标记文件、窗口任务、优先级抢占、就绪后原地重排
- 未实现：原生目录右侧的缓存状态徽标、手动缓存/清理入口（见 §8）

## 3. 验证 C：微信读书双向进度同步

### 3.1 真实请求字段（源码证据）

上传走 `POST /web/book/read`，`weread_protocol.c: send_position()` 组包字段：

| 字段 | 含义 | 本次是否使用 |
| --- | --- | --- |
| `b` | 书籍 ID（`encode_id` 编码） | 是 |
| `c` | 章节 ID（`encode_id` 编码） | 是 |
| `ci` | 章节序号 | 是 |
| `co` | **章内文本偏移**（服务端坐标系） | 是，核心定位 |
| `pr` | 全书进度百分比 | 是 |
| `ct` / `ts` / `rn` / `sg` | 客户端时间、时间戳、随机数、签名 | 是（协议要求） |
| `ps` / `pc` | 阅读会话标识（来自阅读页响应） | 是 |
| `rt` | 本次阅读时长（秒） | 是 |

读取走 `wr_remote_position_with_chapters()`，返回章节 ID + `co` + `pr`。

**结论：服务端提供的是章节级 + 章内偏移级定位，不是页码。** 与需求中 `book_id + chapter_id + chapter_offset` 的结构天然吻合。

### 3.2 本地统一结构

```
book_id  = wr_book_t.id
chapter  = 章节在 chapterInfos 中的序号（= spine 序号）
offset   = 云端 co（章内文本偏移），本地字节偏移仅在设备内部使用
pct      = 云端 pr
```

本地分页位置（第几页）**不参与上传**——页码随字号/行距/机型变化，上传即错。

### 3.3 映射机制：为什么不是"估算"

缓存章节的 XHTML 里，每段文字前都带有 `<!--wr-co:N-->` 标记（`render_html()` / `render_plain()` 中的 `marker()`），N 就是服务端坐标系下的偏移。因此：

- 上传：本地字节偏移 → 找最近的 `wr-co` 标记 → 得到 `co`（`map_position()` + `html_weread_position()`）
- 下载：`co` → 找标记 → 得到本地字节偏移 → 定位到页（`map_position()` 反向）

映射是**查表**，不是按比例估算。这是当前实现已具备的能力，本次改造沿用，未改动映射算法。

### 3.4 精度边界（如实记录）

1. `co` 绑定服务端正文版本。同一本书若服务端改版（修订、换图、重排），旧 `co` 会指向别处。当前无版本校验。
2. 上传后有一个**真实往返校验**：`send_position()`（非时长路径）会重新拉取远端位置并要求 `co` 完全相等，否则视为失败。这是现成的精度证据链。
3. 封面/前言等非正文页的 `co` 可能落在章节外，`map_position()` 在 `offset==0` 时降级为章首（已有处理）。

### 3.5 未实现：多设备冲突处理

现状行为：**下载永远覆盖本地**。手机读到第 30 章、墨水屏离线停在第 25 章，联网后执行"下载进度"会直接把本地改成第 30 章；反过来"上传进度"会用第 25 章覆盖云端。

需求要求"不能直接覆盖"。设计建议（未实现，列为下一步）：

```
若 本地.chapter < 云端.chapter 且 本地最后阅读时间 < 云端更新时间
   → 默认采用云端，但保留本地位置为"回到上次位置"入口
若 本地.chapter > 云端.chapter
   → 默认采用本地，提示"本机进度更新，是否上传"
若 章节相同、co 差值 < 阈值
   → 视为同一位置，取较新时间戳
```

需要服务端进度时间字段；`wr_remote_position` 目前未解析该字段，需在协议层补取（未做，不能凭现有响应断言一定存在）。

## 4. 最终架构

```
┌──────────────────────────────────────────────────────────────┐
│ 书架（app_weread）                                            │
│  点击书籍 → wr_book_path() 成功？→ 直接开原 EPUB               │
│            └ 失败 → wr_open_book()：写标记文件 + 备好章节目录   │
│                     → 立即进阅读页（不等下载）                 │
└───────────────────────────┬──────────────────────────────────┘
                            │ 同一路径
┌───────────────────────────▼──────────────────────────────────┐
│ 阅读页（app_book）· 未改动排版/分页/书签/字体                  │
│  book_open(path) → book_source → 虚拟解析器 → 虚拟书源         │
│  读到占位章 → rc_tick() 收到"已就绪" → 原地重排续读            │
└───────────────────────────┬──────────────────────────────────┘
                            │ provider（纯本地，绝不在主任务联网）
┌───────────────────────────▼──────────────────────────────────┐
│ weread_cache：章节存储 + 虚拟书源                              │
│  t/c<N>.xhtml  i/<hash>.<ext>  m/c<N>.meta(uid/len/crc)        │
│  状态判定：meta 一致 + 长度一致 = READY，否则 NOT_CACHED/STALE │
└───────────────────────────┬──────────────────────────────────┘
                            │ 单 worker 任务（优先级 2）
┌───────────────────────────▼──────────────────────────────────┐
│ WR_PREFETCH：窗口补章                                          │
│  优先：读者等待的章节（占位正文被读取时登记）                    │
│  其次：窗口 [cursor, cursor+10) 内第一个未就绪章                │
│  单章失败只结束本轮，已完成的章全部保留                         │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 三个关键设计决定

1. **磁盘即索引**。不再维护第二份"章节索引文件"：`m/c<N>.meta` 存在且长度/CRC 与正文一致就是 READY。少一份索引 = 少一种断电后不一致，也不会出现"索引说缓存了、文件却没了"。
2. **标记文件即身份**。书籍路径上先放一个自描述占位文件（`WRVBOOK1` + book/owner/章数）。书架、历史、进度、书签全部按路径工作，因此**都不需要改**；整书组装完成后 `rename()` 原子替换，路径不变，进度连续。
3. **网络只在一个任务里**。阅读主任务只读本地文件；需要网络时只投递任务通知（`wr_prefetch_nudge`），不做阻塞调用。

### 4.2 断电与中断安全

- 章节：先写 `c<N>.xhtml` 并 `fsync`，再写 `c<N>.meta`；meta 是提交点。断电最多丢一章，不会出现"半章可读"。
- 标记文件：`fopen("wb")` 覆盖 + `fsync`；文件要么是完整标记，要么是旧标记。
- 整书组装：写 `<path>.part` → 校验章数 → `rename()` 原子替换；失败只删 `.part`。
- 去重：同一 URL 的图片只落一次盘；同一章节的并发请求由单 worker 串行化，不存在重复下载。

## 5. 缓存窗口与优先级

- 窗口：`[当前章, 当前章 + 10)`，由 `WR_WINDOW_CHAPTERS` 定义。
- 优先级：
  - P0 读者当前等待章（占位正文被读取 → 立即登记，任务若在跑会自然抢占）
  - P1 窗口内第一个未就绪章
  - P2 窗口随读者移动（每完成一章游标推进）
- 并发：单 worker 串行，等价"并发 1"。未采用 2 并发的原因：`wr_reader()` 依赖 keep-alive 连接与全局 Cookie 会话，多任务并发会争用同一会话与 PSRAM；单任务已能满足"边读边补"。
- 取消/失败：`wr_cancelled()` 在每章边界检查；失败只结束本轮，不删除已完成的章。

## 6. 与"整书缓存"的兼容

| 场景 | 行为 |
| --- | --- |
| 已有完整 EPUB | `book_open()` 解析器不认标记 → 走原 ZIP 路径，一切如旧 |
| 分章中，用户点"缓存全书" | `wr_cache()` 识别标记文件（不再当损坏缓存删除），`chapter_ready()` 跳过已下载章节，只补缺口，最后组装并原子替换标记 |
| 组装完成后再打开 | 路径上是真 EPUB → 走原 ZIP 路径，分章数据成为历史缓存 |
| 清缓存 | 删除 `stage-*` 目录即回到"未缓存" |

## 8. 尚未解决的问题（按优先级）

1. **目录徽标未做**。需求第五阶段要求原生目录每行右侧显示已缓存/未缓存/缓存中/失败。需要改 `app_book.c` 的目录行绘制，触及 9675 行 UI 文件，本轮未动，避免在未实机的情况下引入界面回归。
2. **进度冲突未处理**（见 §3.5）。当前是覆盖语义。
3. **`book_progress` 键含文件大小**：标记文件与最终 EPUB 尺寸不同，整书组装后首次打开会丢失一次本地进度（云端进度可补回）。
4. **全书百分比偏低**：虚拟源的 `total` 只累计已缓存章节字节，未缓存章计 0，因此显示百分比在缓存过程中偏小。章内定位与云端同步不受影响（云端用 `co` + `pr`）。
5. **服务端整本直发 ZIP** 时逐章路径无法承接，已回落并提示使用"缓存全书"。
6. **TOC 2048 章上限**未放大。
7. **并发度固定为 1**，未做"按内存/网络动态调整"（需求给的是"建议 2，须结合设备动态调整"；单任务串行是更保守的起点）。

## 9. 实机验证清单（L3/L4）

### 9.1 前置

1. 刷入本分支固件，`idf.py monitor` 或串口日志留存。
2. 日志过滤：`WEREAD`、`WRCACHE`、`book_progress`、`app_book`。
3. 准备三本书：纯文本小说（>200 章）、图文混排书、图片密集书（每章 >5 图）。

### 9.2 必测项与判定

| # | 场景 | 判定标准 | 关键日志 |
| --- | --- | --- | --- |
| 1 | 首次打开未缓存书 | 点击后 ≤3 s 进入阅读页，显示占位正文 | `WRCACHE virtual open` |
| 2 | 只缓存第一章即阅读 | 首章可翻页，目录为全书 | `chapter staged` |
| 3 | 后台缓存 10 章时继续阅读 | 翻页无卡顿（主观 + 帧耗时日志） | `cache chapter … elapsed_ms` |
| 4 | 正文含图片章节 | 图片正常显示，无坏图 | `images=` |
